## 2. 다른 PC에서 시작하는 법

### 2.1 설치
1. **Unity Hub + Unity 6000.3.19f1 + WebGL Build Support** (다른 버전으로 열지 않는다).
2. **Git** (원격 push 권한).
3. **Python 3** + `pip install openpyxl pillow pymupdf` (엑셀→CSV, 이미지·PDF 확인).
4. (itch 업로드할 PC만) **butler**: `C:/Users/user/butler/butler.exe` 위치 기준(`Tools/itch_deploy.sh`의 `BUTLER` 변수, 다르면 환경 변수 `BUTLER`로 지정), `butler login` 한 번.
5. (선택) Claude Code 데스크톱 앱, Claude in Chrome 확장(GA4·itch·팀 보드 Neeko.work를 로그인된 크롬으로 볼 때).
6. Git Bash (스크립트가 bash).

1. `git clone https://github.com/MoraDoraR1/DragonWasHere.git` (또는 `git pull`). 마지막 커밋은 아래 7장 참고.

## 4. 작업 도구·명령 (자주 쓰는 것)

### 4.1 데이터 테이블 (가장 주의)
- **`Docs/20261012_데이터테이블_Ver02.xlsx`는 그림 요소가 있어 openpyxl로 저장하면 안 된다.** zip 안의 시트 XML(`xl/worksheets/sheetNN.xml`)의 셀 `<v>`만 바꿔 다시 묶는다. 데이터는 4행부터(1행 한글 이름, 2행 컬럼명, 3행 타입), A열 ID로 행을 찾는다. 시트 번호: building=sheet11, unit=sheet12, drop_item=sheet13, drop_group=sheet14, upgrade=sheet18 (workbook.xml·rels로 확인 가능).
- 수정 절차: 백업 → 셀 XML 수정 → `python Docs/Tools/export_csv.py Docs/20261012_데이터테이블_Ver02.xlsx Docs/Data` → `git diff --stat Docs/Data`로 의도한 CSV만 바뀌었는지 확인 → 바탕화면 원본에 같은 파일 복사 → Build All.
- Build All 배치모드(에디터 닫힌 상태): `Unity.exe -batchmode -nographics -quit -projectPath <프로젝트> -executeMethod DWH.Editor.SceneBuilder.BuildAll -logFile Logs/build_all.log` → `Assets/_Project/Data/GameDatabase.asset` 갱신, `Game.unity`도 다시 만들어짐(커밋에 포함).
- 데이터 흐름: 엑셀 → CSV → `CsvImporter` → `GameDatabase.asset`. EditMode의 `RulesTests` 등은 `CsvImporter.LoadInMemory()`로 **CSV를 직접 읽는다**(테스트 사본에 `Docs/Data`도 동기화해야 함).

### 4.2 빌드·배포
- 웹 빌드(팀 테스트, is_dev=1): `Unity.exe -batchmode -nographics -quit -projectPath <프로젝트> -buildTarget WebGL -executeMethod DWH.Analytics.Editor.DwhWebBuild.BuildTestBatch -logFile Logs/itch_build_test.log` → `Builds/Web_Test/`, `Builds/Web_Test.zip`. 출시용은 `BuildReleaseBatch` → `Builds/Web_Release`.
  - wasm-opt가 간헐적으로 접근 위반(3221225477)으로 죽는다 → 그냥 다시 빌드하면 된다.
  - 보관용 사본 이름: `Builds/YYYYMMDD_웹빌드_VerNN_Claude.zip` (지금 `20261014_웹빌드_Ver04_Claude.zip`).
- itch 업로드: `bash Tools/itch_deploy.sh test` (빌드+업로드) / `bash Tools/itch_deploy.sh test --skip-build` (이미 만든 빌드만). 출시는 `release`. 올린 뒤 itch 편집 페이지에서 butler 업로드가 "This file will be played in the browser"인지 확인.
- 로컬 웹 확인: `python -m http.server 8123 --directory Builds/Web_Test` (Claude 데스크톱이면 `.claude/launch.json`의 `web-test`로 미리보기). 콘솔에 `[DWH Analytics] 이벤트명 {...}`가 찍힌다. page_exit 컨텍스트는 콘솔에서 `exitTracker.context`.

### 4.3 테스트
- 테스트는 **사본**에서: `C:\Project\DragonWasHere_Test`(EditMode→PlayMode), `C:\Project\DragonWasHere_Test2`(밸런스 봇 등 동시 실행). 동기화: `robocopy <원본>\Assets <사본>\Assets /MIR` (ProjectSettings, Packages, **Docs\Data**도 같은 방식). Library·Logs는 건드리지 않는다.
  - **Git Bash에서 robocopy를 부르면 인자 변환 때문에 실패(종료 코드 16)한다. PowerShell에서 돌린다**: `foreach ($f in 'Assets','ProjectSettings','Packages','Docs\Data') { robocopy "C:\Project\DragonWasHere\$f" "C:\Project\DragonWasHere_Test\$f" /MIR /NFL /NDL /NJH /NJS /NP }` (종료 코드 0·1은 정상). 보조 에이전트가 "동기화했다"고 해도 실패했을 수 있으니, 데이터를 바꿨으면 사본의 CSV·GameDatabase.asset 값을 직접 확인한다(10-14에 사본이 옛 데이터로 돈 적 있음).
- 사본 폴더로 **cd 한 뒤** 실행해야 `-logFile Logs/...`가 사본 안에 생긴다.
- EditMode: `Unity.exe -batchmode -nographics -projectPath . -runTests -testPlatform EditMode -testResults Logs/editmode.xml -logFile Logs/editmode.log`
- PlayMode: 같은 명령에 `-testPlatform PlayMode` — **`-nographics`를 붙이면 URP에서 크래시(139)** 나므로 빼고 돌린다.
- 밸런스 봇: PlayMode `-testFilter "DWH.Tests.BalanceSimulationTests.Bot_PlaysToEnding"` ([Explicit]이라 이름으로 지정해야 돈다, 1~3분). 결과 `Logs/balance_sim.md`. 실험용 환경 변수: `DWH_SIM_OVERRIDES=<파일>`(줄마다 `stage_id 항목 배율`, 항목 nhp·ahp·aatk·lhp·latk·uhp·uatk), `DWH_SIM_ATK_SCALE`, `DWH_SIM_LM_SCALE` 등. 봇은 판마다 결과가 꽤 흔들린다(같은 데이터로 엔딩 38~53판).
- 빠른 컴파일 확인: `python Tools/compile_check.py` — PlayMode의 `DWH.Analytics.Recent` 오류 2개와 DWH.Analytics 새 파일 인식 못 함은 도구 한계(Unity에선 정상).
- 현재 기준: EditMode 75, PlayMode 31(1개 [Explicit] 제외).
