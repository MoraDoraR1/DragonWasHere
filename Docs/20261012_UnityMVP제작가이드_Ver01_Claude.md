## 3. 데이터 파이프라인

### 3.1 엑셀 → CSV
엑셀 시트 1개가 CSV 1개가 됩니다(Define·ERD 제외, 20개).

- 2행이 컬럼명, 3행이 자료형, 4행부터 데이터입니다.
- **빈칸 = 해당 없음**입니다. 0으로 읽지 말고 "없음"으로 처리합니다.
- 엑셀을 고치면 스크립트를 다시 돌리고, Unity에서 임포트 메뉴를 다시 누릅니다.

`Docs/Tools/export_csv.py` (Ver02로 실행 확인함, 20개 파일 생성)
```python
"""데이터 테이블 엑셀 → CSV (시트 1개 = 파일 1개).
규칙: 2행 = 컬럼명, 3행 = 자료형, 4행부터 데이터. Define·ERD 시트는 건너뜀.
사용: python export_csv.py <엑셀 경로> <출력 폴더>"""
import csv, os, sys, openpyxl
src, out = sys.argv[1], sys.argv[2]
os.makedirs(out, exist_ok=True)
wb = openpyxl.load_workbook(src, data_only=True, read_only=True)
for ws in wb.worksheets:
    if ws.title in ("Define", "ERD"): continue
    rows = list(ws.iter_rows(values_only=True))
    cols = [i for i, h in enumerate(rows[1]) if h]
    names = [rows[1][i] for i in cols]; types = [rows[2][i] for i in cols]
    def cell(v, t):
        if v is None: return ""
        if t in ("int", "bool") and isinstance(v, float) and v.is_integer(): return str(int(v))
        return str(v)
    with open(os.path.join(out, f"{ws.title}.csv"), "w", encoding="utf-8", newline="") as f:
        w = csv.writer(f); w.writerow(names)
        n = 0
        for r in rows[3:]:
            if r[cols[0]] is None: continue
            w.writerow([cell(r[i], t) for i, t in zip(cols, types)]); n += 1
    print(f"{ws.title}.csv  {len(names)}열 {n}행")
```
```bash
python Docs/Tools/export_csv.py Docs/20261012_데이터테이블_Ver02.xlsx Docs/Data
```

### 3.2 Unity에서 읽기
- `Editor/CsvImporter`(메뉴 `DWH/Import Data`)가 CSV를 ScriptableObject로 바꿉니다. 시간이 없으면 런타임에 `Resources`나 `TextAsset`으로 읽어도 됩니다.
- **ID는 문자열**입니다(`stg101`, `upg505`, `res6000106`). 테이블끼리는 ID로 연결되고, 연결 관계는 엑셀 `ERD` 시트에 있습니다.
- **enum 컬럼은 정수**입니다. 의미는 `enum.csv`의 (`enum_type`, `value`)에 있습니다. C# enum으로 옮길 때 값을 그대로 맞춥니다.
- **문구는 모두 `string.csv`에 있습니다.** `*_str` 컬럼의 키로 `ko`/`en`을 찾습니다. 효과 이름은 `effect_type_name_{코드}` 키입니다.
- **리소스는 모두 `resource.csv`에 있습니다.** `res_id` → `res_path`(`리소스/` 폴더 기준 경로)로 찾습니다(5장).
- **const.csv**는 키-값 표입니다. `value_type`(int/float/bool)으로 변환합니다.

### 3.3 데이터 검증 테스트 (EditMode, 먼저 만들 것)
- **참조 무결성**: 모든 FK가 대상 테이블에 있어야 합니다.
  - `*_str` → string, `res_id*` → resource, `prereq_*` → upgrade, `stage_id` → stage, `drop_group` → drop_group
  - 엑셀 쪽에서는 이미 0건임을 확인했습니다.
- **리소스 파일 존재**: `resource.res_path`의 파일이 모두 `Art/`에 있어야 합니다.
- **MVP 경로**: `mvp_order` 1~14가 빠짐없이 이어지고, `mvp_next_stage_id`를 따라가면 stg101부터 stg702까지 14개입니다.

- **옅은 픽셀**: 건물·유닛·자원 PNG에 알파 1~8 픽셀이 조금 있습니다. 임포트할 때 알파 8 이하를 0으로 지웁니다. 건물은 이미 바닥에 붙어 있어서 잘라 낼 필요가 없습니다.
- **드래곤 파츠는 절대 잘라 내지 않습니다**(좌표가 어긋남).

**드래곤 조립** (`dragon_part.csv`, 단계별 `location.txt`와 같은 값)
- 파츠마다 `res_id`, `pivot_x/y`(회전점, 이미지 왼쪽 위 기준 px, y는 아래로 증가), `parent_part_id`, `attach_x/y`(부모 이미지에서 붙는 점)가 있습니다.
- 위치 계산: `child.origin = parent.origin + attach - child.pivot`. 몸통 원점은 (0,0)이고, Unity에서는 y 부호를 뒤집고 PPU로 나눕니다.
- **레이어 순서는 `layer_order`(1 = 맨 앞)**: 1 날개, 2 뒷다리, 3 꼬리, 4 앞다리, 5 윗머리, 6 아랫머리, 7 목, 8 몸통, 9~11 반대편(앞다리·뒷다리·날개). `sortingOrder = 20 − layer_order`입니다.
  - 옛 문서(4.1.5)와 1·2번이 바뀌었습니다.
- 반대편(`is_back = 1`)은 같은 스프라이트를 어둡게(0.6) 씁니다.
- 원본은 왼쪽을 봅니다. 루트를 `localScale.x = -1`로 뒤집습니다.
- **성장 단계가 바뀌면 그 단계의 파츠 세트로 통째로 교체**합니다. 단계별 그림이 이미 커져 있으므로 `size_pct`는 모두 100이고, 따로 키우지 않습니다.

**없는 리소스와 대체 처리**
| 없는 것 | 처리 |
|---|---|
| 황금 건물·황금 공격 건물 | 같은 건물 스프라이트를 **셰이더나 색 곱하기로 황금색 처리**(보너스 황금 건물, 감별안 황금화 모두) |
| 충격파·회전 회오리·몸통 박치기 이펙트 | 이펙트 없이 진행(팀 결정). 필요하면 파티클로 간단히 |
| 부서진 건물 상태 이미지(_s1~_s4) | 흰 플래시 + 흔들림. `const.building_break_state_*`는 나중에 쓸 자리 |
| 콤보 연출 이미지 | 없음. UI 기획서상 텍스트 표시 |
| 사운드 | 없음 |
| 탄(투사체) | 단색 스프라이트 |
| 뒤 테마 배경(`bg_st*_2_*`) | 배경은 시대 공용이라 MVP에는 필요 없음 |

## 6. 시스템별 구현 메모

동작 세부는 `임시unity제작.md`의 해당 절을 보고, **수치는 반드시 테이블에서 읽습니다.**

### 6.1 드래곤 기본 (`dragon`, `const`)
- 능력치: 체력 100, 기력 100, 공격력 20, 공격 속도 2, 이동 300 px/s, 점프 높이 200 px, 치명타 배율 150% 등. 모두 `dragon.csv`에 있습니다.
- 피로: 스테이지 시작 시 초당 기력 감소 `fatigue_start`(1), `fatigue_interval_sec`(10초)마다 +1.
- 체력 0 또는 기력 0이면 실패하고, `end_slowmo_sec` 슬로모션 후 결과 화면으로 갑니다.
- 마우스 유도와 자동 이동은 `임시unity제작.md` 4.1.2·8.5.1, 점프 물리는 8.6을 따릅니다. `mouse_idle_sec` = 3입니다.

### 6.2 건물 (`building`)
- 스테이지마다 유형(`building_type`: 1 일반, 2 공격, 3 랜드마크, 4 황금)별 1행입니다. **`count`개를 만들고 `hp`, `atk`, `atk_speed`, `atk_range`(px)를 그대로 씁니다.**
  - `hp`는 허들·벽 배율이 이미 들어간 **최종값**입니다. 코드에서 배율을 곱하지 않습니다.
- 그림은 `res_id_1~3` 중에서 고릅니다. 시드는 `스테이지 순번 × 1000 + 건물 순번`으로 고정합니다.
- 배치: 간격 `const.building_spacing_px`(150), 랜드마크는 전체의 가운데, 공격 건물은 고르게 분산합니다(`임시unity제작.md` 3.4).
- 탄: 공격 건물은 지면 직선 탄, 랜드마크는 세 높이 수평 탄입니다(8.5.2). 피해는 `atk`입니다.

### 6.3 공중 유닛 (`unit`)
- 스테이지당 3행이고, `spawn_sec`(3/10/25초)에 1마리씩 등장합니다. 그 전에 클리어하면 나오지 않습니다.
- 공격 속도 0.5 aps이고 드래곤을 조준합니다. 패시브·액티브 모두로 처치할 수 있습니다. 동작은 `임시unity제작.md` 4.5 구현 메모를 따릅니다.

### 6.4 드랍·정산 (`drop_group`, `drop_item`)
- 건물이나 유닛이 파괴되면 `drop_group`의 모든 행(`item_id`, `min_count~max_count` 개)을 쏟습니다. 지금은 min = max입니다.
- `drop_absorb_delay_sec`(0.5초) 뒤 드래곤에게 흡수되며, `drop_item.gold_value`만큼 세션 골드에 더합니다.
- 그다음 골드 배율(탐욕·황금 혈통)을 곱합니다.
- 실패해도 그때까지 얻은 골드는 지급합니다.
- 결과 화면: 획득 골드, 파괴 수, 보너스 진입 여부, 최고 스테이지, "바로 다시 출격"(출격 전 저장, 첫 판에서는 비활성).

### 6.5 MVP 진행 (`stage`, `const.mvp_mode`)
- `mvp_mode = 1`이면 다음 규칙으로 진행합니다.
  - 시작 스테이지는 `mvp_order = 1`(stg101)입니다.
  - 클리어하면 `mvp_next_stage_id`로 갑니다. 빈칸이면 엔딩입니다.
  - 보스 판정은 `stage_type` 대신 **`mvp_stage_type`**(2 = 보스)으로 합니다.
  - HUD 번호는 `{시대}-{stage_no}`라서 x01 → x-1, x02 → x-2로 그대로 맞습니다.
- `mvp_mode = 0`(CBT)이면 `next_stage_id`와 `stage_type`을 씁니다. 코드는 두 모드를 모두 지원하게 짭니다.
- 배경은 `bg_far_res`, `bg_mid_res`, `bg_ground_res`입니다. 원경은 고정, 중경은 바닥의 1/3 속도, 바닥은 카메라와 1:1로 움직입니다.
- HUD 상단: "{시대 이름} | {테마 이름}" + 스테이지 이름(`stage_name_*`) + 남은 건물.

### 6.6 보너스 스테이지
- 클리어 순간 기력이 `bonus_min_stamina`(10) 이상이면 진입합니다.
- 황금 건물(유형 4 행)만 나옵니다. 그림은 그 테마 일반 건물을 **황금색으로 칠해서** 씁니다.
- 기력 감소는 `bonus_stamina_drain_mult`(2)배이고, 체력·기력 회복은 모두 무시합니다. 공중 유닛은 나오지 않습니다.
- 기력이나 체력이 0이 되거나 황금 건물을 모두 부수면 끝나고, 어느 경우든 클리어로 처리합니다.

### 6.7 업그레이드 트리 (`upgrade`)
- **28노드**입니다. `category`(1 공통 ~ 5 패시브 스킬)는 트리의 갈래입니다.
- **해금**: `prereq_id_1`, `prereq_id_2`가 모두 1레벨 이상이면 열립니다. 빈칸이면 조건이 없습니다.
- **최대 레벨**: `max_level`이고, 0이면 무제한입니다.
- **비용** (골드 코인):
  - `cost_mult`가 있으면 `n레벨 비용 = base_cost × cost_mult^(n−1)`입니다(무제한 노드 9개, 1.5).
  - 없으면 `n레벨 비용 = base_cost + add_cost × (n−1)`입니다.
  - 환생 특성 "용의 지혜"(비용 감소)를 곱하고 올림합니다.
- **효과**: `effect_type_1/2`, 수치 = `base_value + add_value × (n−1)`, 연산 `value_op`(1 합산, 2 배수). 효과 코드별 적용 대상은 아래 표입니다.
- **아이콘**: `res_id`. 노드 상태(기본, 구매 가능, 잠김, 최대)는 UI 에셋 `03_트리노드와탭`을 씁니다.
- 스킬 노드 연결 (테이블 `prereq_id` 기준)
  - 용의 각성 → 몸통 박치기 → 돌진, 회전 회오리
  - 회전 회오리 → 거대 회오리, 충격파, 낙뢰
  - 충격파 → 충격 범위 / 낙뢰 → 천둥 폭풍
  - 용의 각성 → 파이어 브레스 → 지옥불, 파이어 볼 → 연속 파이어 볼
  - 종말의 용 = 충격파 + 낙뢰
- 성장 단계: 업그레이드에 쓴 골드를 **평생 누적**해 `dragon_growth.req_gold`(0 / 1,000 / 10만 / 1억)를 넘으면 외형이 바뀝니다.
  - 10-12 결정으로 환생하면 성장 단계도 초기화됩니다. 누적값을 회차 기준으로 리셋합니다.

**효과 코드 (`enum effect_type`) 적용 표** `[임시 해석]`은 기획서에 정의가 없어 정한 해석입니다.

- 충격파만 기획안 기준으로 바뀌었습니다: 꼬리로 땅을 내리쳐 주변 공격, 쿨 10초, 150%, 공격 건물 1초 기절, 화면 흔들림 0.3초. 범위는 **맞닿은 건물 1개 + 충격 범위 레벨만큼 양옆 건물**입니다(옛 문서의 unit 단위 범위가 아님).

### 6.8 패시브 스킬
- 6종: 몸통 박치기(기본 보유), 파이어 브레스, 파이어 볼, 낙뢰, 충격파, 회전 회오리. 해당 업그레이드 노드가 1레벨이 되면 해금됩니다.
- 모션 슬롯(머리: 파이어 볼·브레스·낙뢰 / 몸통: 돌진·충격파·회전 회오리)은 같은 슬롯 안에서 `motion_queue_interval_sec`(0.3초) 간격으로 순차 발동합니다(`임시unity제작.md` 4.3·4.1.5).
- 이펙트: `resource` type 80
  - 파이어 볼(`res8000004`), 브레스(`res8000005`), 낙뢰(`res8000006` 골드 / `res8000007` 블루), 연쇄 번개(`res8000008`, `res8000009`)
  - `frame_count`, `frame_rate`, `loop`를 읽어 재생합니다.
  - 시트는 비고(memo)에 있는 격자(4×3 등)로 자릅니다.

### 6.9 스타터·콤보
- 스타터: 일반 스테이지 시작마다 발동합니다(보너스 제외).
  - 시간은 `const.starter_*`, 판정은 `starter_grade`(Great 200%·양옆 5, Good 130%·양옆 2, Fail 0), 게이지 속도·폭은 `starter_stage`입니다.
  - 판정 표시 이미지는 `starter_grade.res_id`입니다. 연출 순서는 `임시unity제작.md` 4.7을 따릅니다.
- 콤보: 직전 파괴 후 `combo_keep_sec`(3초) 안에 다음 건물을 부수면 콤보가 이어집니다.
  - `combo.min_combo` 이상이면 그 단계 문구(`combo_praise_*`)를 `text_color`로 표시합니다. 형식은 "999 COMBO!! + 칭찬 문구"(UI 기획서 p11)이고, 끊기면 사라집니다.

### 6.10 환생·액티브 (`rebirth_trait`, `active_skill`, `const.rebirth_rp_divisor`)
- **환생 해금 (10-13 변경)**: 첫 환생은 3-2 도달 시 열리고, 그 뒤에는 언제든 횟수 제한 없이 할 수 있습니다.
- **환생 포인트**: `floor(√(이번 회차 누적 획득 골드) ÷ rebirth_rp_divisor)`(10)
- **초기화**: 업그레이드 레벨, 골드, 진행(1-1부터), 성장 단계
- **유지**: 환생 포인트, 환생 특성, 액티브 습득 단계, 환생 횟수
- **특성 6종** (환생 포인트로 구매)
  - 비용: `base_cost + add_cost × (n−1)`
  - 효과: 코드표와 같습니다. 태고의 분노·황금 혈통은 레벨당 +20%입니다.
- **환생 화면**: 보유 포인트, "지금 환생하면 +N P", 특성 6장, 액티브 3장, 2단계 확인(`임시unity제작.md` 4.9).
- **액티브 3종**: `prereq_upgrade_id` 노드가 1레벨 이상이면 습득할 수 있습니다.
  - 비용: 환생 포인트 `base_cost + add_cost × (n−1)`. 메테오는 1레벨 0이라 해금만 되면 무료입니다.
  - 단축키 1·2·3과 클릭으로 씁니다. 출격할 때 사용 횟수를 채우고, 보너스 스테이지에서는 남은 횟수를 이어 씁니다.
  - ⚠ **세션당 사용 횟수는 테이블에 없습니다.** `임시unity제작.md` 4.4의 레벨별 1 / 1 / 2 / 2 / 3회를 씁니다. 데이터로 빼려면 `active_skill`에 `uses_per_run` 컬럼 추가를 요청해 주세요.
  - 이펙트: 메테오 `res8000001`, 허리케인 `res8000002`, 지진 `res8000003`

### 6.11 HUD·문구·성장
- HUD 배치와 동작은 `임시unity제작.md` 4.12와 UI 기획서를 따릅니다.
- 대미지 숫자: `damage_popup_sec` 동안 떠오르고, 한국식 단위(만·억)로 표기합니다.
- 언어: 설정에서 한/영을 바꾸고, 모든 문구는 `string`에서 읽습니다. 폰트는 NotoSansKR(TMP 패키지)입니다.
- 성장 외형: 단계가 오르면 파츠 세트를 바꾸고 "○○로 성장!"을 띄웁니다.

## 8. 지표 수집 (출시용, P0)

- 구조: Unity WebGL → `AnalyticsService.cs` → `analytics.jslib` → Firebase JS SDK → GA4. Unity Firebase SDK는 WebGL을 지원하지 않습니다. user_id는 게임이 만든 UUID입니다.
- **P0 이벤트 8개**: `session_start`, `run_start`, `run_end`, `upgrade_purchase`, `outgame_exit`, `rebirth_unlocked`, `rebirth`, `game_complete`
- 이벤트 파라미터, firebaseConfig, 팀 테스트 방법(is_dev)은 공유 계획 페이지를 기준으로 합니다: https://claude.ai/artifact/1SgUfQdZacXzi4khHyhXzP
- 일정: 수집 모듈은 게임과 별개로 먼저 만들고, 게임이 완성되면 이벤트 호출만 연결합니다. 10-14에 itch.io 비공개 페이지에서 팀 테스트, 10-15에 공개합니다.

## 9. 밸런스 확인

수치는 시뮬레이션으로 맞춘 **1차 값**입니다. 구현이 끝나면 아래와 비교합니다(`20261012_MVP밸런스_Ver01_Claude.md`).

| 확인 항목 | 시뮬레이션 기대값 |
|---|---|
| 업그레이드 없이 1-1 | 첫 판 클리어, 보너스 진입 |
| 1회차 | 1-2 약 3판, 2-2 약 3판, **3-2에서 막힘 → 환생**(약 24 RP) |
| 2회차 | 3-2를 약 2판 만에 넘고 **5-2에서 막힘 → 환생**(약 190 RP) |
| 3회차 | 7-2 약 6판 → 엔딩 |
| 전체 | 약 44판, 약 70~75분 |
| 환생 없이 벽 | 3-2, 5-2 모두 8판 넘게 못 넘음 |

**알려진 위험**
- **체력 생존**: 시뮬레이션은 기력·시간만 판정했습니다. 공격 건물·랜드마크·공중 유닛 피해 때문에 실제로는 더 어려울 수 있습니다. 1-2와 보스에서 체력으로 죽는 비율을 먼저 봅니다. 너무 어려우면 해당 행의 `atk`를 낮춥니다.
- **환생 직후 구간**: 다시 올라가는 구간과 4-2·6-2는 쉽게 지나갑니다. 의도한 "환생하면 확 강해지는" 체감인지 확인합니다.
- **효과 해석**: 6.7 표의 `[임시 해석]` 항목은 기획 확인이 필요합니다.
- 가능하면 `BalanceSimulationTests`(EditMode)로 봇 진행을 재현해, 수치를 바꿀 때마다 위 표를 다시 뽑습니다.
