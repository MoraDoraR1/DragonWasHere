# DragonWasHere

https://moradorar1.github.io/DragonWasHere/

Unity 6 (6000.3.19f1) · URP · Input System 기반 프로젝트.

## 작업 규칙

### 1. 세션 시작 시
- 대화를 시작하면 **반드시** 아래 파일을 먼저 읽고 파악한다.
  - `README.md` (이 문서의 규칙)
  - `작업내용.md` (지금까지의 작업 이력)
  - `메모.md` (추후 계획)
- 파악한 뒤 **특이사항을 먼저 보고**한다. (미완료 작업, 이어서 할 일, 확인이 필요한 문제 등)

### 2. 문서 최신화
- 작업을 진행하면 `작업내용.md`와 `메모.md`를 **항상 최신 상태로 업데이트**한다.
- 작업이 끝날 때마다 바로 기록하고, 세션이 끝날 때까지 미루지 않는다.

### 3. 언어
- 모든 답변은 **한국어로만** 작성한다.

### 4. 기준 문서 동기화
- 구현 기준은 아래 순서를 따른다. 문서끼리 다르면 위에 있는 것이 우선이다.
  1. `Docs/20261012_데이터테이블_Ver02.xlsx` (→ `Docs/Data/*.csv`): 모든 수치, ID, 문구, 리소스 경로
  2. `Docs/20261012_UnityMVP제작가이드_Ver01_Claude.md`: MVP 범위, 데이터 읽는 법, 작업 순서
  3. `Docs/20261012_MVP밸런스_Ver01_Claude.md`: 밸런스 근거와 검증 목표
  4. `Docs/임시unity제작.md`: 시스템 동작 세부(연출, 판정, 물리). 수치와 리소스 경로는 옛 값이라 쓰지 않는다
- 수정은 항상 저장소 `Docs/`의 파일에 먼저 한다.
- 수정한 뒤에는 같은 내용을 바탕화면 원본(`Desktop/DragonWasHere_기획서및리소스/` 아래 같은 이름의 파일)에도 반영해 두 파일을 같게 유지한다.
- 엑셀을 고치면 `python Docs/Tools/export_csv.py Docs/20261012_데이터테이블_Ver02.xlsx Docs/Data`로 CSV를 다시 만들고 Unity에서 `DWH > Import Data`를 실행한다.

### 5. 커밋
- 사용자가 요청할 때만 커밋한다. 작업이 끝나도 자동으로 커밋하지 않는다.

### 6. itch.io 업로드
- 업로드는 **이 PC에서 butler로만** 한다. itch 웹 화면에서 파일을 직접 올리거나 바꾸지 않는다.
- 테스트 빌드: `bash Tools/itch_deploy.sh test` (채널 `html5-test`), 출시 빌드: `bash Tools/itch_deploy.sh release` (채널 `html5`). 이미 만든 빌드만 올릴 때는 뒤에 `--skip-build`.
- 올린 뒤 itch 편집 페이지에서 butler 업로드에 "This file will be played in the browser"가 켜져 있는지 확인한다.

## 컨벤션

### 파일명
| 구분 | 형식 | 예시 |
|---|---|---|
| 문서 파일 | `날짜_파일이름_버전_작업자` | `20260720_컨셉기획서_Ver01_오승명` |
| 자료 파일 | `날짜_용도이름_작업자` | `20260720_리소스이미지_오승명` |

- 날짜는 `YYYYMMDD` 8자리로 쓴다.
- 버전은 `Ver` 뒤에 두 자리 숫자를 붙인다. (`Ver01`, `Ver02` …)

### 커밋 메시지
형식: `[태그]날짜_내용_작업자`

| 태그 | 용도 | 우선도 | 예시 |
|---|---|---|---|
| `[MOD]` | 수정 | **1** (가장 높음) | `[MOD]20260720_플레이어이동속도조정_오승명` |
| `[ADD]` | 추가 | 2 | `[ADD]20260720_플레이어컨트롤러_오승명` |
| `[DEL]` | 삭제 | 3 | `[DEL]20260720_템플릿안내파일_오승명` |

- 날짜는 커밋하는 날의 `YYYYMMDD`로 쓴다.
- Claude가 커밋할 때는 작업자를 `Claude`로 쓴다.
- **한 커밋에 여러 종류의 변경이 섞이면** 우선도가 가장 높은 태그(숫자가 작은 것) 하나만 제목에 쓴다. 나머지 변경은 커밋 설명(본문)에 적는다.

```
[MOD]20260720_플레이어이동개선_오승명

- 수정: 이동 속도와 가속도 값 조정
- 추가: 대시 입력 액션 추가
- 삭제: 사용하지 않는 구버전 이동 스크립트 제거
```

### 피그마
- 아직 정하지 않았다. (`메모.md` 참고)

## 문서 구성

| 파일 | 용도 |
|---|---|
| `README.md` | 프로젝트 개요와 작업 규칙 |
| `작업내용.md` | 실제로 **작업한 내용**을 날짜별로 누적 기록 |
| `메모.md` | 아직 작업하지 않았지만 **추후 계획할 것**을 기록 |

### 기록 방식
- `작업내용.md`: 최신 날짜가 위로 오도록 날짜별 섹션(`## YYYY-MM-DD`)을 만들고 무엇을, 왜, 어떻게 했는지 적는다.
- `메모.md`: 계획 항목을 체크리스트(`- [ ]`)로 적는다. 작업을 시작하거나 끝내면 해당 항목을 정리하고 결과를 `작업내용.md`로 옮긴다.
